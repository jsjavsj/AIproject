A one-time setup.
A more connected planner.

The website owner completes these steps once. Afterward, each student can connect their own Google account in Customize → Connections.

What connects?

Calendar imports selected calendars for the previous 30 days and next 180 days. Classroom imports published assignments, announcements, and class materials from active courses the student is enrolled in. Shared files, videos, forms, and teacher links appear in the Classroom feed. Sync is manual and read-only. Assignment completion in Daylight is a personal checklist; it does not turn in work.

1. Create a Google Cloud project

Open the Google Cloud Console and create or choose a project for Daylight. In APIs & Services → Library, enable both Google Calendar API and Google Classroom API.

2. Configure Google Auth Platform

Open Google Auth Platform (or OAuth consent screen). Add an app name, support email, and developer contact. Choose the audience appropriate for your project: an internal school app if eligible, or an external app.

While testing an external app, keep publishing status in Testing and add the Google accounts that will test the competition demo under Test users. Some school administrators restrict third-party apps.

Add these read-only scopes under Data Access:

  • openid and email for identifying the connected account
  • https://www.googleapis.com/auth/calendar.calendarlist.readonly
  • https://www.googleapis.com/auth/calendar.events.readonly
  • https://www.googleapis.com/auth/classroom.courses.readonly
  • https://www.googleapis.com/auth/classroom.coursework.me.readonly
  • https://www.googleapis.com/auth/classroom.announcements.readonly
  • https://www.googleapis.com/auth/classroom.courseworkmaterials.readonly

3. Create a web client ID

Under Clients → Create client, choose Web application. Add your deployed website origin under Authorized JavaScript origins, for example https://your-project.vercel.app. Also add http://localhost:5173 and http://127.0.0.1:5173 for local testing.

Origins include the protocol and port when present, with no path or trailing slash. Add each custom domain separately. Stable deployment domains are easier to authorize than changing preview URLs. This popup token flow does not use an application redirect endpoint.

Copy the Client ID, which ends in .apps.googleusercontent.com. The client ID is public. Do not put a client secret in the website, repository, or Settings.

4. Configure Vercel and redeploy

In the Vercel project, open Settings → Environment Variables. Add GOOGLE_CLIENT_ID with the copied client ID. Select the environments you intend to use, then redeploy. The build creates the public browser configuration automatically.

For a local test, open Daylight → Customize → Connections → Website owner setup. Paste the public client ID into Google OAuth web client ID and save. This testing setting only affects the current browser.

5. Connect and import

  1. Open Customize → Connections.
  2. Click Sign in with Google, choose your account, and allow read access to both Calendar and Classroom in the same permission flow.
  3. Select the calendars and courses you want from that account, then click Sync selected in each section.
  4. Click an imported event to open its original in Google Calendar. Open the Classroom tab to read announcements and browse Files & materials. Attachments on assignments appear here too. Click a file to open it in a new tab; the same Google account must have permission to view it. Files are linked, not downloaded or backed up by Daylight.

Google access tokens stay in memory and expire; reconnect after refreshing the page or when a session expires. Imports and layout choices are saved in this browser. They do not provide cloud backup for your Daylight plans.

Upgrading an existing connection: add the announcements and courseworkmaterials read-only scopes above to your Google Auth Platform configuration, then sign in again and approve the additional permissions before syncing.

Troubleshooting

  • Origin mismatch: add the exact current website origin to the OAuth web client's authorized JavaScript origins.
  • Access blocked: add your account as a test user; check your school’s app-access policy.
  • Permission denied: enable both APIs and allow the requested read scopes.
  • No courses: use an account enrolled as a student in active Classroom courses. This version does not import courses you only teach.
  • Popup blocked: allow popups for the website and click Connect again.
  • Session expired: reconnect, then sync. Existing imported data is preserved if a sync fails.

Before a public launch

Testing is appropriate for an invited competition demo. Google may require OAuth app verification, verified domains, and an accurate privacy policy before broad public use of these scopes. Follow the requirements displayed in your project's Google Auth Platform console.
