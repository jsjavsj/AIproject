한 번의 설정으로
더 편리한 플래너를 만들어요.

웹사이트 운영자가 아래 설정을 한 번 완료하면, 각 학생이 맞춤 설정 → 연결에서 자신의 Google 계정을 연결할 수 있어요.

어떤 데이터를 가져오나요?

캘린더는 지난 30일과 앞으로 180일의 일정을 가져와요. 클래스룸은 학생으로 참여 중인 활성 수업의 공개된 과제, 공지사항, 수업 자료를 가져와요. 공유 파일, 동영상, 설문지, 웹사이트 링크는 클래스룸 탭에 표시돼요. 동기화는 수동이며 읽기 전용이에요. Daylight에서 과제를 완료해도 클래스룸에 제출되지는 않아요.

1. Google Cloud 프로젝트 만들기

Google Cloud Console에서 Daylight용 프로젝트를 만들거나 선택하세요. API 및 서비스 → 라이브러리 (APIs & Services → Library)에서 Google Calendar API와 Google Classroom API를 모두 활성화하세요.

2. Google 인증 플랫폼 설정

Google Auth Platform 또는 OAuth 동의 화면을 여세요. 앱 이름, 지원 이메일, 개발자 연락처를 입력하고 프로젝트에 맞는 대상을 선택하세요. 학교 내부 앱을 사용할 수 있는 경우 내부 사용자를, 그 외에는 외부 사용자를 선택할 수 있어요.

외부 앱을 테스트할 때는 게시 상태를 테스트(Testing)로 유지하고, 대회 시연에 사용할 계정을 테스트 사용자(Test users)에 추가하세요. 학교에서 외부 앱 접근을 제한할 수도 있어요.

데이터 액세스(Data Access)에 다음 범위를 추가하세요. 아래 주소는 그대로 복사하세요.

  • openid, email: 연결된 계정 확인
  • https://www.googleapis.com/auth/calendar.calendarlist.readonly
  • https://www.googleapis.com/auth/calendar.events.readonly
  • https://www.googleapis.com/auth/classroom.courses.readonly
  • https://www.googleapis.com/auth/classroom.coursework.me.readonly
  • https://www.googleapis.com/auth/classroom.announcements.readonly
  • https://www.googleapis.com/auth/classroom.courseworkmaterials.readonly

3. OAuth 웹 클라이언트 만들기

클라이언트(Clients)에서 웹 애플리케이션(Web application) 유형의 OAuth 클라이언트를 만드세요. 승인된 JavaScript 원본(Authorized JavaScript origins)에 실제 Vercel 주소(예: https://your-project.vercel.app)를 추가하세요. 로컬 테스트용으로 http://localhost:5173과 http://127.0.0.1:5173도 추가하세요.

원본 주소에는 프로토콜과 필요한 포트 번호를 포함하고, 경로나 마지막 슬래시는 넣지 마세요. 별도 도메인은 각각 등록해야 해요. 자주 바뀌는 미리보기 주소보다 고정 배포 주소를 사용하는 것이 편리해요. 이 앱의 팝업 로그인 방식은 별도의 리디렉션 엔드포인트를 사용하지 않아요.

.apps.googleusercontent.com으로 끝나는 클라이언트 ID(Client ID)를 복사하세요. 이 ID는 공개해도 되는 값이에요. 클라이언트 보안 비밀번호(Client secret)는 웹사이트, 저장소, 설정 화면에 넣지 마세요.

4. Vercel 환경 변수 설정 후 다시 배포

Vercel 프로젝트의 Settings → Environment Variables에서 GOOGLE_CLIENT_ID를 추가하고 복사한 클라이언트 ID를 값으로 넣으세요. 사용할 환경을 선택한 다음 다시 배포하세요. 빌드 과정에서 브라우저용 공개 설정이 자동으로 생성돼요.

로컬에서 테스트하려면 Daylight의 맞춤 설정 → 연결 → 웹사이트 운영자 설정을 여세요. Google OAuth 웹 클라이언트 ID에 공개 ID를 입력하고 저장하세요. 이 테스트 설정은 현재 브라우저에만 적용돼요.

5. Google 연결 및 데이터 가져오기

  1. 맞춤 설정 → 연결을 여세요.
  2. Google로 로그인을 누르고 계정을 선택한 후 캘린더와 클래스룸 읽기 권한을 허용하세요.
  3. 가져올 캘린더와 수업을 선택한 다음 각 항목의 선택 항목 동기화를 누르세요.
  4. 가져온 일정은 Google 캘린더 원본으로 이동할 수 있어요. 클래스룸 탭에서 공지사항을 읽고 파일 및 자료를 확인하세요. 과제에 첨부된 파일도 표시돼요. 파일은 새 탭에서 열리며, 해당 Google 계정에 파일을 볼 권한이 있어야 해요. Daylight는 파일 링크만 저장하고 파일 내용을 다운로드하거나 백업하지 않아요.

접근 토큰은 메모리에만 보관되며 만료돼요. 페이지를 새로고침하거나 연결이 만료되면 다시 로그인하세요. 가져온 항목과 화면 설정은 이 브라우저에 저장돼요. Google 로그인은 Daylight 계획의 클라우드 백업 기능이 아니에요.

기존 연결에 새 기능 추가: 공지사항과 수업 자료용 읽기 권한을 위 목록대로 Google 인증 플랫폼에 추가하세요. 다시 로그인해 추가 권한을 허용한 후 동기화하세요.

문제 해결

  • 원본 주소 불일치: 현재 웹사이트의 정확한 원본 주소를 승인된 JavaScript 원본에 추가하세요.
  • 접근 차단: 계정을 테스트 사용자에 추가하고 학교의 외부 앱 정책을 확인하세요.
  • 권한 거부: 두 API를 모두 활성화하고 요청한 읽기 권한을 허용하세요.
  • 수업이 보이지 않음: 활성 수업에 학생으로 참여 중인 계정인지 확인하세요. 선생님으로만 참여 중인 수업은 가져오지 않아요.
  • 팝업 차단: 이 웹사이트의 팝업을 허용하고 다시 연결하세요.
  • 연결 만료: 다시 로그인한 후 동기화하세요. 동기화가 실패해도 기존에 가져온 데이터는 유지돼요.
로그인했는데 Google에서 접근을 거부하나요?

권한 동의와 API 사용 설정은 별도예요. 해당 연결 카드에 표시된 오류 코드를 확인하세요.

  • SERVICE_DISABLED 또는 accessNotConfigured: OAuth 클라이언트 ID를 만든 동일한 Google Cloud 프로젝트를 선택하세요. API 및 서비스 → 라이브러리에서 Google Calendar API와 Google Classroom API를 사용 설정하고 몇 분 후 다시 시도하세요.
  • ACCESS_TOKEN_SCOPE_INSUFFICIENT 또는 insufficientPermissions: Google 인증 플랫폼 → 데이터 액세스에서 위의 읽기 권한을 확인한 후 다시 연결하고 허용하세요.
  • 요청 한도 관련 코드: 나중에 다시 시도하고 계속 실패하면 API 할당량을 확인하세요.

개인 Gmail 계정에는 학교 관리자가 없어요. Google에서 계정 제한을 안내한 경우에만 조직 정책을 확인하세요. 다른 오류가 계속되면 Daylight에 표시된 서비스 이름과 오류 코드를 알려 주세요.

전체 공개 전에 확인하세요

초대한 사용자만 참여하는 대회 시연에는 테스트 모드를 사용할 수 있어요. 불특정 다수에게 공개할 때는 Google에서 OAuth 앱 검증, 도메인 확인, 정확한 개인정보처리방침 등을 요구할 수 있어요. 프로젝트의 Google 인증 플랫폼에 표시된 요건을 확인하세요.
